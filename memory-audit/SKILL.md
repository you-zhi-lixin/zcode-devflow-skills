# memory-audit（记忆深度对账）

记忆没有 repo 那样的强制对账机制，写进去的东西只会悄悄过期——过时记忆比空记忆更阴险，它让 agent 停止重新核实事实。本技能按周期做一次全面核验，把记忆库拉回与仓库现实一致。

**何时跑**：每收口完 2-3 张票（checkpoint 变更清单尾行有计数）；用户感觉「AI 又开始犯常识错／会话质量下降」时；/orient 在简报里转介时（重写级手术、孤岛合并、重建索引）；用户点名「体检记忆」时。

先读 [`../checkpoint/references/memory-discipline.md`](../checkpoint/references/memory-discipline.md)（读不到→停下告知用户，可从套件 git 副本恢复）——四层地盘、两问测试、重写律、体检红线全在那份合同里。

## 过程

1. **盘点**：列出记忆目录全部文件（行数/字节数），读 MEMORY.md 与每条记忆全文。备好仓库现实：票据状态（按 `docs/agents/issue-tracker.md` 词表读：`.scratch/*/issues/` 或远端 tracker）、`git log --oneline -30`、现行 spec/设计文档。
   完成＝全库在手，没有未读的记忆文件。

2. **逐文件核验**（只读阶段，不改任何文件）。每条记忆过五类检查：
   - **过时**：断言对照仓库现状逐句验证，失效的记下「记忆:行 ↔ 仓库:行」证据；超 30 天未决的「假设：」条目列入
   - **矛盾**：两条记忆对同一事实说法不同；同一文件内部前后矛盾
   - **越界**：进度细节／✅ 条目混进现状条目（重写律）；repo 已记录的内容被整段复制（两问测试第 2 问）；平台主动写入的不合规条目（未过两问测试的）；AGENTS.md 记忆套件地图与合同脱钩（合同修订后地图没跟上）
   - **形态**：现状条目 >10KB、索引行 >150 字符、断言缺日期锚、description 或索引钩子句与正文脱节、未标注的「假设」、frontmatter 缺字段（name/description/type 缺一即病）、name 与文件名（去 .md）不一致、超 60 天悬挂的 [[双链]]
   - **对账**：MEMORY.md 索引行与目录文件双向核对——索引有而文件无＝断链（删该行或请用户恢复文件）；文件有而索引无＝孤儿（补建索引行）
   另做**孤岛排查**：在记忆根下找本项目同前缀或关键词撞车的其他记忆目录（初筛 `grep -il` 只回文件名；Read 候选文件时用 Windows 绝对路径），发现候选→问用户是否同一项目。
   完成＝发现清单，每条带证据与建议处置。

3. **拍板**：发现按严重度排序，弹窗分批呈报（每批 ≤4 问，推荐项放第一；**同类低风险小病可打包成一问**——「这 N 条都按推荐处理？全部照办（推荐）／一条条告诉我」，毒化与过时类仍逐条拍板）。处置只有六种：**重写**（按重写律整文件重写）／**就地修正**（只把错的几句改对）／**搬进存档**（完结内容移入 repo 交付存档文件，记忆留指针）／**删除**／**合并**（孤岛处置，防护见下）／**重建索引**（仅 MEMORY.md 缺失/损坏时：逐文件读 frontmatter 的 name/description 重新生成索引行，整文件重写——这是索引律「只做单行编辑」的唯一例外，须经用户拍板后执行）。
   **合并防护三件套**：①合并前弹窗复述两库各 2-3 条代表性记忆供用户指认哪库是本项目，对同一事实两库口径冲突的逐条对仓库核验后才许并；②仍有效的事实并入本库时，在本库加一行溯源（「以下 N 条合并自 xxx@日期」），误合并可发现可回滚；③旧库废弃并在其索引顶部留一行指针指向本库。
   **不可逆处置（删除／合并）的推荐项默认保守**：「暂不合并／保留」放第一，用户明说才执行。
   核对后仍有效的红线只标「仍有效」，不动。
   完成＝每条发现都有裁决。

4. **执行**：按裁决批量改，同一动作内同步 MEMORY.md 索引（只做单行编辑；重建索引除外）。**清台账**：本次处置掉的病在台账 `.scratch/memory-health.md` 追加一行清账（作后续计数的分界线）。
   完成＝裁决全部落地，或明示挂起清单。

5. **报告**：核验 N 条记忆／发现 M 处／处置明细（重写 x、修正 y、搬存档 z、删 w、合并 v、重建索引 r），以及下次体检的建议时点（按收口计数推算）。报告尾行提醒：本库共 N 条记忆、约 X KB，均为普通文件，建议不定期把整个 memory 目录打包备份到 repo 之外的自选位置（网盘/移动盘）——不进 repo、不参与召回，只为防误删/换机。
   完成＝用户看完知道记忆库这轮发生了什么、下次何时再查。
