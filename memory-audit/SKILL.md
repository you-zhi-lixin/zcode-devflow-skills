# memory-audit（记忆深度对账）

记忆没有 repo 那样的强制对账机制，写进去的东西只会悄悄过期——过时记忆比空记忆更阴险，它让 agent 停止重新核实事实。本技能按周期做一次全面核验，把记忆库拉回与仓库现实一致。

**何时跑**：每 2-3 个大批次收尾后；用户感觉「AI 又开始犯常识错／会话质量下降」时；/orient 在简报里转介时（重写级手术、孤岛合并）；用户点名「体检记忆」时。

先读 [`../checkpoint/references/memory-discipline.md`](../checkpoint/references/memory-discipline.md)（读不到→停下告知用户）——四层地盘、两问测试、重写律、体检红线全在那份合同里。

## 过程

1. **盘点**：列出记忆目录全部文件（行数/字节数），读 MEMORY.md 与每条记忆全文。备好仓库现实：票据状态（`.scratch/*/issues/` 或 `docs/agents/issue-tracker.md` 指向的 tracker）、`git log --oneline -30`、现行 spec/设计文档。
   完成＝全库在手，没有未读的记忆文件。

2. **逐文件核验**（只读阶段，不改任何文件）。每条记忆过四类检查：
   - **过时**：断言对照仓库现状逐条验证，失效的记下「记忆:行 ↔ 仓库:行」证据
   - **矛盾**：两条记忆对同一事实口径不同；同一文件内部前后矛盾
   - **越界**：进度细节／✅ 条目混进现状条目（重写律）；repo 已记录的内容被整段复制（两问测试第 2 问）；平台主动写入的不合规条目（未过两问测试的）
   - **形态**：现状条目 >10KB、索引行 >150 字符、断言缺日期锚、description 与正文脱节、未标注的「假设」

   另做**孤岛排查**：在记忆根下找本项目同前缀或关键词撞车的其他记忆目录（Read 候选文件时用 Windows 绝对路径），发现候选→问用户是否同一项目。
   完成＝发现清单，每条带证据与建议处置。

3. **拍板**：发现按严重度排序，弹窗分批呈报（每批 ≤4 问，推荐项放第一）。处置只有五种：**重写**（按重写律整文件重写）／**回填修正**／**压缩归档**（完结内容移入 repo 交付存档或史册文件，记忆留指针）／**删除**／**合并**（孤岛处置：仍有效的事实并入本库，旧库废弃并在其索引顶部留一行指针指向本库）。核对后仍有效的红线只标「仍有效」，不动。
   完成＝每条发现都有裁决。

4. **执行**：按裁决批量改，同一动作内同步 MEMORY.md 索引（只做单行编辑）。
   完成＝裁决全部落地，或明示挂起清单。

5. **报告**：核验 N 条记忆／发现 M 处／处置明细（重写 x、修正 y、归档 z、删 w、合并 v），以及下次体检的建议时点。
   完成＝用户看完知道记忆库这轮发生了什么、下次何时再查。
