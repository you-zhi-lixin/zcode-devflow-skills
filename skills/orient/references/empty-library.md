# 空库岔路（orient 第 2 步 veteran 分支细则）

前提：repo 已有记忆套件地图或成套票据，或 git 史 ≥5 笔提交，且 MEMORY.md 与 memory 目录皆空——疑似 veteran 空库（换机／重装／误删 vs 首装空库，库内无法自辨）。正文已完成的规定动作：`ls ~/.zcode/cli/memories/projects/` 排查同机旧库。

## 岔路

1. **同机旧库命中**（ls 看到本项目的旧目录，多产生于改名／搬家）→ 转介 /memory-audit 合并，不走下方路径。
2. **未命中** → 弹窗问用户：「此前在这个项目用过记忆吗？」
   - **用过** → 两条路径：
     - **从旧机／备份拷回** memory 目录（`~/.zcode/cli/memories/projects/<项目目录>/memory/`）；拷回后先按 orient 第 4 步做一次轻体检确认索引↔文件一致，再出简报。
     - **明示放弃重建**：放弃前二次确认（提示回收站/OneDrive 版本历史或可救），并如实告知损失——user/feedback 型记忆 repo 无处可捞，重建只能回收 repo 侧约定；放弃后走第 6 步口径起步。
   - **没用过（首装存量）** → 走第 6 步口径起步，并说明首条记忆来自首次 /checkpoint。

## 红线

- 规定动作（ls 同机旧库）与「用过吗」弹窗不可跳过——跳过即复现"存量首装被误诊为换机／误删"的已修 bug。
- 放弃重建的二次确认与损失告知不可省——不可逆决定不压成一次弹窗。
