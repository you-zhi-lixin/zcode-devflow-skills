# memory-audit（记忆深度对账）

对记忆库做周期性全面核验，把记忆库拉回与仓库现实一致（判据与动机见 memory-discipline.md「两问测试」）。

**何时跑**：每收口满 2-3 行（按台账收口行数计，每轮一行；checkpoint 清单末尾体检提醒行有计数）；用户反馈 AI 出现常识性错误时；/orient 转介时（重写手术、孤岛合并、重建索引）；点名「体检记忆」时。
词表分工：体检＝本轮周期性维护这件事；对账＝记忆↔仓库现实对照（定义见合同）；核验＝第 2 步的逐句检查动作。

先读 [`../checkpoint/references/memory-discipline.md`](../checkpoint/references/memory-discipline.md)（读不到→停下告知：从插件缓存或 `~/.zcode/skills/` 同名目录找副本恢复，没有→重装本插件，本轮中止）。

## 过程

1. **盘点**：列记忆目录全部文件（行数／字节），读 MEMORY.md 与每条记忆全文——全库扫描与证据 grep 派只读子代理（每轮 ≤2 并发，需要时多轮，只回结论；记忆 ≤5 条且总量 <20KB 的库不派，主窗口直接读），避免主窗口塞满文件内容。**派单 prompt 必带两条技术提醒**（子代理看不到本技能正文）：Read 记忆文件一律用 Windows 绝对路径（不展开 `~`）；Bash 命令里含空格／中文的路径加引号。备好仓库现实：
   - 票据状态（含票面 Comments——agent-brief、handoff 便签路径一并取用；按 `docs/agents/issue-tracker.md` 词表；读不到或无终态约定→按合同「票据终态约定」执行，报告注明口径来源；终态判定按票种取前缀：实现票 done、决策／task 票 resolved，容忍日期批注）
   - `git log --oneline -30`
   - 现行 spec/设计文档（含远端 spec 票正文）与 `docs/research/` 笔记（存在则读）；CODING_STANDARDS.md 与交付存档（docs/archive.md 等记忆指针指向物）存在则纳入
   - repo 有 GLOSSARY.md／docs/adr/／`.out-of-scope/` 则一并纳入；GLOSSARY-MAP.md 存在＝multi-context 仓库，各 context 的 GLOSSARY 与 `src/<context>/docs/adr/` 一并纳入
   **复跑早退**：盘点检测到 MEMORY.md 顶部「> ⚠ 冻结：」指针或台账「冻结：」清账行（任一即认，总则见合同）→收缩为单项对账：指针目标存在且仍是现行真相源（目标再迁移才按过时呈报），其余五类检查不跑、发现不呈报，报告不预约下次体检时点（不写该行，见第 5 步）。

2. **逐文件核验**（只读）。五类检查（加孤岛排查共六类；第五类「索引对账」专指索引↔文件，与合同「对账发现＝记忆 vs 票面／git」区分）：
   - **过时**：断言对照仓库逐句验证，记「记忆:行 ↔ 仓库:行」证据；超 30 天未决的「假设：」列入
   - **矛盾**：两条记忆对同一事实说法不同；同文件前后矛盾
   - **越界**：进度细节/✅ 混进现状条目；repo 已记录内容整段复制；平台写入未过两问测试；AGENTS.md 地图与合同脱钩
   - **形态**（三组）：
     容量——现状条目 >10KB；索引行 >150 字符（按字符数，不是字节）；索引条目 ≥30（预警，见合同红线）
     元数据——缺日期锚；未标注假设；frontmatter 缺 name/description/type；name 与文件名不符
     脱节——description 或钩子句与正文脱节（缺正文关键限定＝脱节；措辞风格差异不算）；超 60 天悬挂 [[双链]]；正文链接自身（[[自链]]）；[[双链]]指向不存在文件且库内有相近 name（错链）；索引行残缺解析不出文件名
   - **索引对账**：索引↔文件双向核对——索引有文件无＝断链；文件有索引无＝孤儿
   另做**孤岛排查**：记忆根下找同前缀或关键词撞车的目录（初筛 `grep -il` 只回文件名；Read 候选用 Windows 绝对路径）。**先查全局台账 island-checks.md**——已有结论的目录跳过；发现候选→弹窗附命中关键词列表（词×处数，不展示对方内容）问用户是否同一项目，结论落 island-checks.md。

3. **拍板**：发现按严重度排序（毒化类——写成事实的假设＞过时／矛盾＞越界＞形态＞索引对账），弹窗分批呈报（每批 ≤4 问，推荐项放第一；同类低风险小病可打包成一问「都按推荐处理？全部照办／一条条告诉我」，毒化与过时类逐条呈报）。处置七种：
   - **重写**（重写律）
   - **就地修正**（补注记＝形式性；口径澄清改动断言含义＝内容性，呈报时注明级别；存量台账的无前缀示例行——紧邻建档说明行、与数据行同构——经用户指认后补「格式示例」前缀，形式性）
   - **搬进存档**（完结内容移入 repo 交付存档，记忆留指针）
   - **删除**
   - **合并**（孤岛，防护见下）
   - **重建索引**（仅 MEMORY.md 缺失／损坏：逐文件按 frontmatter 重生成索引行——标题按索引律用 description 中文浓缩，报告注明「标题为重建生成」；整文件重写，索引律唯一例外，经用户拍板后执行；重写须原样保留「> ⚠ 冻结：」指针行）
   - **冻结／移交**（库整体被外部记忆体系接管，或处置对象在另一现行库不可写）：MEMORY.md 索引顶部插单行指针，**固定以「> ⚠ 冻结：」开头**（机器可读标记，与合并指针区分）——`> ⚠ 冻结：<日期>移交至 <现行真相源路径>（迁移凭证）`；逐条处置转台账`挂账`行并注明「已移交」（orient 不再重提），追加一行以「冻结：」开头的清账行。指针自身是快照：目标再迁移即按过时处置；冻结库不再收口计数、不触发落后横幅与升级告警（见合同计数规则与冻结库总则）。处置过拍板
   **合并防护**（全局台账已有裁决的候选跳过发现问，但防护①仍必走——它是合并前的安全步骤）：
   ① 先复述两库各 2-3 条代表记忆（取索引钩子句即可）供用户指认哪一库属于本项目，口径冲突的逐条对仓库核验
   ② 并入本库的事实加溯源行（「以下 N 条合并自 xxx@日期」）
   ③ 旧库废弃并在索引顶部留指针指向本库
   合并完成后在 island-checks.md 追加「已合并」行。
   删除／合并的推荐项默认保守（「暂不合并／保留」放第一）。核对后仍有效的红线只标注「仍有效」，不动。
   完成＝每条发现都有裁决（未获应答／应答不掌握的按合同「拍板弹窗」节兜底——形式性按推荐执行，内容性挂起落`挂账`行）；打包问答「不清楚」→形式性项照推荐执行（标注「不掌握·按推荐」），内容性项拆回逐条走不掌握兜底。

   禁止的捷径：
   - 「抽查几条出全库结论」——五类检查是逐句核验，抽样结论禁止冒充全量。
   - 「孤岛候选直接判同项目」——必须先查 island-checks.md，合并防护①不可跳。
   - 「发现顺手改掉不上报」——见第 3 步完成判据。

4. **执行**：按裁决批量改，同步 MEMORY.md 索引（单行编辑；重建索引除外）。处置掉的病在台账追加清账行；未获应答／应答不掌握的内容性处置逐条追加`挂账`行（格式见合同）——下次 orient 简报据此重提，拍板执行后划账。

5. **报告**（聊天输出排版按合同「聊天输出排版」节执行——普通 Markdown、加粗小标题＋普通列表、禁代码块／围栏）。版式样例（下列引用块**去掉行首 `> ` 后**就是用户该看到的样子；`> ` 只是本文件的排版标记，**不要照抄进回复**）：

   > **体检报告**
   >
   > 核验 <核验数> 条 · 发现 <发现数> 处
   >
   > - 处置明细一条一行：动作＋对象＋结果
   >
   > **下次体检时点**：<按收口计数推算的时点>
   > **备份提醒**：本库 <条数> 条约 <库体积> KB，均为普通文件，建议不定期把整个 memory 目录备份到 repo 之外（网盘／移动盘；不进 repo、不参与召回，防误删／换机）

   尖括号为占位符，输出时替换为实际值、不保留括号。处置明细无处置时写「本轮无处置」。下次体检时点按收口计数推算，识别口径与不计数行见合同计数规则；冻结库不预约（报告不写时点行）。备份提醒行每轮必带，<条数>＝库内记忆条数、<库体积>≈库体积，从盘点数据取。
