# project-init（项目地基）

两套体系的地基一次铺好：Matt 工程技能（grilling→to-spec→to-tickets→implement）要 tracker 配置；记忆套件（orient/checkpoint/memory-audit）要 AGENTS.md 地图与首条记忆。

先读 [`../checkpoint/references/memory-discipline.md`](../checkpoint/references/memory-discipline.md)（读不到→停下告知：从插件缓存或 `~/.zcode/skills/` 同名目录找副本恢复，没有→重装本插件，本轮中止）——seed 记忆要过两问测试与写入四问。

## 项目分流（第 1 步判定，判完走对应行）

| 项目状态 | 路径 |
|---|---|
| 冻结库（MEMORY.md 顶部指针） | 只告知已移交＋路径，跳过第 2 步子块与 seed，完成按「已说明跳过」计 |
| 存量（repo 有实质内容且无记忆套件子块） | 走第 1、2、4 步：铺地图＋交代节奏；seed 默认跳过，由第 4 步「存量起步」接管 |
| 新项目 | 第 1-4 步全套：tracker 缺失在拍板单①节引导 setup，铺地图＋seed＋节奏 |

（表只指路；各态判定条件以第 1 步为准。）

## 过程

1. **前置检查**（只读）：新项目还是存量——repo 已有实质代码、票据或 git 史（任一即可）且 AGENTS.md/CLAUDE.md 无「记忆套件」子块＝存量；git 仓库有无；`docs/agents/issue-tracker.md` 有无（Matt setup 产出物）；AGENTS.md/CLAUDE.md 有无；记忆库空否（MEMORY.md 顶部有「> ⚠ 冻结：」指针→告知用户本项目记忆已移交（路径见指针），跳过第 2 步子块更新与 seed，完成判据按「已说明跳过」计；**库空且无冻结指针→顺带一句告知（不弹窗不阻塞，用户不接话照常继续）：想搬旧项目的记忆过来，直接说「体检记忆」即可由 /memory-audit 按合并流程办**）；台账 `.scratch/memory-health.md` 有无（有→读「拒绝记忆」类病行，后续询问据此跳过）。
   tracker 缺失→**新项目**：列入拍板单第①节（先跑 /setup-matt-pocock-skills，中断本次，完成后重新输入 /project-init 继续，重跑安全已铺部分自动跳过；本技能禁止代为调用／不跑，继续铺记忆侧地基——工程技能会阻塞要求配置，票走 `.scratch/` 或无票）。**存量项目**：拍板单首行加一行后果说明（工程技能会阻塞要求配置，记忆套件照常可用，票走 `.scratch/` 或无票），不设选项、不阻塞不停下（后续照常走第 2、4 步）。tracker：记录任务清单的载体。
   存量项目→走第 2、4 步（只铺地图＋告知日常节奏，跳过 tracker 分岔与 seed）。
   - **初始化拍板单（全流程唯一确认点）**：前置检查完成时把本技能全部询问并成一张结构化单子一次发出，第 2-4 步按单执行、不再中途弹窗。节序固定、每节只在该节有内容时出现；全部节为空→不弹单，直接铺固定内容。各节候选可点选、附来源指针、末项「以上都不是」；应答兜底照合同「拍板弹窗」节逐条执行，拒绝路径照「拒绝记忆」机制落台账：
     - ① **tracker 缺失**（仅新项目且缺）：先跑 /setup-matt-pocock-skills（中断本次，完成后重新输入 /project-init，重跑安全；本技能禁止代为调用）／不跑，继续铺记忆侧地基（工程技能会阻塞要求配置，票走 `.scratch/` 或无票）
     - ② **AGENTS.md 写入说明**：新建／更新哪些文件＋CLAUDE.md 分工（措辞照第 2 步现行）；「记忆套件」子块在 CLAUDE.md 的，本节含「迁入 AGENTS.md＋删 CLAUDE.md 旧块」拍板项
     - ③ **终态词表登记**：按第 2 步现行规则生成本地／远端建议文案，可点选「写入／不写入」；拒绝→照现行落「拒绝登记」病行，不再弹
     - ④ **seed 三问**：产品给谁用／拍板规矩来源／硬约束——每问附从 repo 证据预生成的候选（README、spec、lint 配置等，附来源指针，末项「以上都不是」）；答不出照现行留空或标「假设：」
     - ⑤ **存量起步**（仅存量未 seed）：要不要现在梳理一条项目现状记忆——要→按第 3 步口径补 seed；不要→照现行落「用户暂不 seed」病行
   门槛：前置检查各分支（新／存量、git、tracker、AGENTS.md／CLAUDE.md、库态、台账病行）都有结论、拍板单已应答或按兜底，才动第一个写操作。

2. **铺 AGENTS.md 协作地图**：固定写 `<repo>/AGENTS.md`——ZCode 官方唯一自动载入的指令文件（CLAUDE.md 专用 Claude Code，ZCode 不保证载入）。项目只有 CLAUDE.md→新建 AGENTS.md，写入说明与分工说明列入拍板单第②节：「记忆套件地图住 AGENTS.md，每次开工自动读；CLAUDE.md 留给读它的其他工具，不动。」Matt setup 写进 CLAUDE.md 的子块不被 ZCode 载入，但其技能按路径读 `docs/agents/*.md`，不受影响——只向用户说明，不迁移。「记忆套件」子块只在 CLAUDE.md 里→迁入 AGENTS.md，CLAUDE.md 侧旧块删除列入拍板单第②节，经拍板后删。
   `## Agent skills` 块不存在则自建，块内追加「记忆套件」子块（已存在则原位更新；周边内容零覆盖）。没跑过 Matt setup→先建议跑 setup 再回来执行本步（第 1 步已明确拒绝的不再问）；此后重跑过 setup→复查子块与「拍板顺序／入口指针」两行是否仍在；被后续 setup 或内置 /init 覆盖丢失→补回。

   ```markdown
   ### 记忆套件

   - 一切记忆写入（含平时主动写入）过两问测试＋写入四问
   - 改现状条目＝整文件重写，不做增量补丁；断言带绝对日期
   - 索引（MEMORY.md）只做单行编辑
   - 续接既有项目的会话（含开场直接派活）先 orient 定位，再动手
   - 开工定位 orient（自动触发）；每票收口 /checkpoint（手动，并勾验收框＋置终态）；每收口满 2-3 行（票或轮）/memory-audit（手动，到值只是提醒，跑不跑由你决定）
   - 手工改过记忆文件后建议跑 /memory-audit 核一遍（手改当下没有自动检查）
   - 细节见 checkpoint 技能的 references/memory-discipline.md

   （本块为记忆套件流程约定：环境回顾、no-op 清理时勿删本块。）
   ```

   另加两行（存在才写，不虚构；落 `## Agent skills` 块内、「记忆套件」子块外同级——不计入子块 ≤10 行）：**拍板顺序**（业务规则以需求真相文件为准，视觉／执行值以设计规范为准，互斥以最新拍板为准）；**入口指针**（需求真相文件、设计规范目录路径）。可推断类信息（架构、目录布局、语言惯例）一律不写。「记忆套件」子块 ≤10 行（按非空行计）。
   **初始化台账**：`.scratch/memory-health.md` 不存在→创建（一行说明＋一行格式示例，**示例行行首必须是「格式示例」四字（冒号全半角均可），且用占位形态**：`格式示例：<日期>｜<类型>｜<内容>`——不含真实类型词与真实日期，从结构上不可能被误计；全类型见合同「记忆健康台账」节；只建档不追加行——初始化不是收口，不进体检计数）；已存在则不动（首部若有无前缀的裸示例行→经用户确认补「格式示例」前缀或删除，形式性）。
   **终态词表登记**（repo 有 `docs/agents/issue-tracker.md` 且其 Conventions 无实现票终态、台账无「拒绝登记」病行时）：按 tracker 类型分支生成建议文案，列入拍板单第③节——**本地**（文档以 Status 行＋验收框为词表）：建议追加「本地实现票收口＝验收全勾＋`Status: done`（可带日期批注）；wayfinder 决策票（含 task 型）＝`Status: resolved`（见其 Wayfinding operations 节）」；**远端**（GitHub/GitLab，票无 Status 字段）：建议在其 Conventions 追加「实现票终态＝验收框全勾＋按本文件 Resolve 节关闭；wayfinder 决策票（含 task 型）走 Resolve 全套」，文案以该文档自身措辞为准、不引入 Status 字段——均经③节拍板后写入；拒绝→台账追加一行`病：用户拒绝终态词表登记（不再主动弹）`，不动 repo 文档，套件按合同「票据终态约定」继续，收口报告注明口径来源；单子未获应答／应答不掌握→按合同兜底并追加`挂账`行（orient 简报重提）。
   门槛：「记忆套件」子块 ≤10 行（按非空行计）、拍板顺序与入口指针两行在位、周边内容零覆盖核对过，第 2 步才算过。

3. **seed 首条项目记忆**（存量默认跳过；已有项目身份类记忆→跳过）：三问已在拍板单第④节收答（每问附 repo 证据预生成候选），按答案写；答不出→不编造，留空或标注「假设：」。过两问测试写 1 条 project 型记忆；repo 已记录的只留指针。无可写→跳过并向用户说明。同步 MEMORY.md 索引（单行追加，≤150 字符）。
   门槛：seed 过两问测试与写入四问（合同）且索引行 ≤150 字符才落盘。

4. **告知日常节奏**：向用户复述日常循环——开工 orient 自动弹简报；每票收口运行 /checkpoint（并收尾票据）；每收口满 2-3 行（票或轮）跑 /memory-audit（计数器到值只是提醒，跑不跑由用户决定）；流程不确定时问 ask-matt（手动技能）。
   **存量起步**：未 seed（＝记忆库无项目身份类记忆）的存量项目向用户说明「首条记忆由首次 /checkpoint 收口生成（空库新建合法）」；要不要现在就梳理一条已在拍板单第⑤节收答——要→按第 3 步口径补 seed；不要→止于说明，不代写，台账追加一行`病：用户暂不 seed（重跑不再问）`。已有项目身份类记忆→不触发（日常节奏交代已含起步路径）。
   **拒绝记忆**：本技能内任何询问被用户明确拒绝→台账追加一行`病`注明「用户拒绝 X，不再主动询问」，重跑时先查台账跳过该询问；弹窗未获应答／应答不掌握→按合同「拍板弹窗」节兜底（形式性可自动执行，内容性必须挂起）＋`挂账`行（orient 简报重提）。
   完成＝按第 1 步分支该执行的第 2-4 步均已执行，跳过项已向用户说明。
   收尾按合同「聊天输出排版」节「接下来可以做」规范列 ≤3 条（编号、第一条标（推荐）），候选固定：1.（推荐）直接开工——下次会话 orient 自动弹进度简报，无需再初始化；2. 跑 /setup-matt-pocock-skills——补齐 tracker 地基，工程管线（grilling→to-spec→to-tickets→implement）才能跑（仅 tracker 缺失时列；拍板单①节已选「先跑」的，此条换为「完成后重新输入 /project-init 续铺」，约几分钟）；3. 首次收口跑 /checkpoint——生成首条项目记忆（存量未 seed 时首条记忆从这里来）。

## 能力边界

- 不代跑 /setup-matt-pocock-skills、不代建 tracker——只引导与说明后果。
- 不写业务内容：「拍板顺序」「入口指针」两行只登记路径与顺序约定，需求真相与设计规范的内容不代写。
- 用户答不出的 seed 问题留空或标「假设：」，不编造项目身份。
- 本技能只铺地基，不验证日常流程是否被遵守——遵守情况由 orient 每次开工轻体检暴露。
