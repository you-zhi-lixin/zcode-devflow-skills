# checkpoint（收口沉淀）

用户输入 /checkpoint 或要求「更新项目记忆」。任务：把本段工作里「下月还为真且 repo 查不到」的事实存进记忆，其余一切留在 repo；票收口时相关票据一并收尾。

先读 [memory-discipline.md](references/memory-discipline.md)（读不到→停下告知：从 `~/.agents/skills/` 同套件目录或插件缓存找副本恢复，没有→重装本插件，本轮中止）。两问测试、写入四问、重写律全在那份合同里，本文件不重复。

## 过程

1. **盘点本段产出**：本会话的提交增量（以上次收口为基准）、票据状态变化、对话拍板、新坑、对工作方式的纠正。用户传了参数就以参数为重点。**源自本套件简报/变更清单的语句不算独立来源**，须回溯票/commit/用户原话。**会话经历过上下文压缩→对话不可靠**：以 git log/票面/diff 为准，对话项逐条确认，拿不准标「假设：」或不写。工作区有未提交改动→先请示是否 commit。
   **票收尾（经用户确认后当场做）**：交付已完成但验收框未勾/Status 未置终态→按 `docs/agents/issue-tracker.md` 词表回写；读不到或无终态约定→按合同「票据终态约定」执行（本地 done／wayfinder resolved），报告注明口径来源。
   - 本地实现票：勾框＋置终态——批注容忍、裸 done、已收口不重复回写，细则全在合同「票据终态约定」
   - 票面 ready-for-human 而交付实际已由本会话完成：不直接回写——弹窗说明矛盾（票面要人工、实作已完成），由用户拍板：勾框置 done／退回重 triage／搁置
   - 远端实现票：先勾正文验收框（命令按 tracker 文档）再关闭
   - wayfinder 决策票（含 task 型）：走 Resolve 全套（动作清单在合同「票据终态约定」；远端另按 tracker 文档 Resolve 节）
   **台账（每轮）**：`.scratch/memory-health.md` 不存在→先创建（格式见合同）再追加一行收口记录（行如 `2026-11-06｜收口｜3 张票收口`）——有票记票数，无票记「轮 N」；commit message 未引用票号→提醒用户（不代改）。
   **repo 外/不可达分支产物**：编排过子代理→向用户确认探索笔记等产物的去向（repo 外目录，或 wayfinder research/prototype 的用后即弃分支（throwaway branch）——分支会被 prune，指针无法保留内容）：票上已有指针的不再重复问指针，改问**内容本体要不要落 repo 交付存档**（判定性结论至少落一份）；本会话运行过 /handoff→核对便签路径已由 handoff 技能留到票 Comments，缺失才问。

2. **过两问测试＋写入四问**（合同）：进度细节（票 done、测试数、commit 号）留 repo；半成品→提醒用户跑 /handoff，记忆侧不写；**ADR 级拍板**（难逆转＋真权衡）→先问用户要不要建 ADR（调用 domain-modeling），拒了再进记忆；纠正若已进 CODING_STANDARDS.md/自动检查→repo 已记录，记忆留指针；值得写的归四种类型标落点；流水账进 repo 交付存档文件，记忆留指针；猜测标「假设：」。

3. **查重与重写**：候选逐条对 MEMORY.md 和相近记忆查——**MEMORY.md 缺失/损坏时先 `ls` 记忆目录逐文件判重，不得仅凭空索引新建**；收尾时在变更清单尾行提醒跑 /memory-audit 重建索引。覆盖同一事实→更新原文件（description 与索引钩子句同步）；被推翻→修正或删除＋同步索引。现状条目按重写律整文件重写：只装「现在长什么样＋非显而易见的挂账」，✅ 勾选与进度细节移出（进度细节留 repo）。删除与否、是否改述拿不准→弹窗带推荐项拍板。repo 已出现 spec/需求真相文件而 AGENTS.md 地图无「入口指针」行→弹窗建议补一行（经用户拍板后才动 AGENTS.md；AGENTS.md 不存在或无「记忆套件」块＝没跑过 /project-init→不代建，转介 /project-init）。本技能各内容性弹窗未获应答→按合同「拍板弹窗」节兜底（形式性可自动执行，内容性必须挂起），挂起项逐条追加台账`挂账`行（行如 `2026-11-06｜挂账｜某记忆过时待重写——用户未应答`；orient 简报重提）。

4. **落盘（防并发覆盖）**：写前重读目标文件与 MEMORY.md——与盘点时不一致→重走第 3 步再写；MEMORY.md 只做单行编辑。写后回读确认持久化——不符（被拒收/改写/重排）→停止写入并报告，视为平台记忆契约变更信号，本轮不再批量写。**异常收尾三件事（按序）**：
   - ① 变更清单如实列「本轮未持久化」项，不虚报成功
   - ② 本轮已过闸的事实落 /handoff 便签或 repo 交付存档，不随会话蒸发
   - ③ 台账追加一行`病：平台写入异常`——**写前先查台账**：已有未划账的同名病行＝跨会话连续第 2 轮→直接告知用户暂停批量写入

   恢复后重跑 /checkpoint：先单笔试探写（写一条最小记忆并回读）→成功则解除暂停照常收口，并追加一行`清账`划掉病行；再失败→本轮止于报告。

   不许走的捷径：
   - 「索引看着正常，跳过 ls 判重」——空索引/断链本身就是病，`ls` 是唯一可靠判据。
   - 「回读扫一眼就行」——拒收/改写/重排只有逐字回读能发现。
   - 「对话内容直接当事实写」——同第 1 步：压缩后对话不可靠，须回溯票/commit/用户原话。

5. **报变更清单**：

   ```
   新建 N／更新 M／删除 K（零变更照常报 0/0/0）
   - 动作｜中文标题（记忆名）｜一句话理由
   尾行：距上次 /memory-audit 已收口 N（数台账收口行，票数或轮次）
   ```

   中文标题取自索引行；删除与说法翻转的注明波及面。满 2-3 行时提醒跑 /memory-audit。
   完成＝变更清单已报（零变更报 0/0/0 即止）。
