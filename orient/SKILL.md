# orient（开工定位）

用户要在既有项目上开工——新会话续接、隔天再战、换窗口、开场直接派活。跑完本技能，用户不用再问任何「我们到哪了」：简报里已经答了在哪、哪张票能开工、下一步敲什么。

先读 [`../checkpoint/references/memory-discipline.md`](../checkpoint/references/memory-discipline.md)（与本技能同级的 checkpoint 技能目录下；读不到→停下告知用户，不凭记忆猜纪律）。四层地盘与体检红线都在那份合同里。

## 过程

1. **定位记忆**：MEMORY.md 索引已随会话自动载入——直接做「去读/不去读」分诊，读索引指到的 project 型现状条目全文。memory 根目录定位不到（如在子代理中运行、系统提示无 memory 说明）→ 用 Bash `ls ~/.zcode/cli/memories/projects/` 按项目名前缀自行定位；仍找不到→按记忆库为空处理（走第 2、6 步）。
   完成＝现状条目在手，索引每条的去读/不去读有判断。

2. **孤岛扫描（空库也要做）**：记忆为空 ≠ 全新项目——同项目换工作区会另起空库，搬家/改名/换打开方式正是孤岛诞生场景。在记忆根下找同前缀目录（如 `shuiling-*`），grep 其余目录 MEMORY.md 的本项目关键词；发现候选→问用户是否同一项目，确认的写入简报「记忆健康」行，合并转介 /memory-audit。库空且确认无孤岛→按全新项目走第 6 步。
   完成＝有/无孤岛有一句话结论。

3. **对账**：拿记忆对照仓库现实——票据状态（`.scratch/*/issues/` 的 Status 行与验收勾选；`docs/agents/issue-tracker.md` 指向远端 tracker 则按其说明查）、spec/计划文档、`git log --oneline -15`。**票面与记忆一致、但与 git/工作树矛盾，也算对账发现**——两个记录可能一起过时。
   完成＝每条现状断言要么验证过、要么进了对账发现清单。

4. **轻体检**：按合同的「体检红线」扫**行级小病**——索引行超 150 字符、断言缺日期锚、description 与正文脱节。≤3 条→列修复清单走第 7 步；**现状条目超 10KB、混入进度细节/✅ 条目、内部矛盾、或孤岛待合并→本技能不扩科，简报转介 /memory-audit**。
   完成＝小病清单在手，或转介决定已做。

5. **输出 standup 简报**：
   - **当前阶段**：一两句，带日期锚与证据（票状态@日期、末次 commit）；来自记忆但未经本步核验的口径标「记忆口径，未复核」
   - **frontier**：可开工的票——判定＝Status 非终态（done/superseded/wontfix）＋blocker 全闭环＋git 无「其实已完成」迹象；状态漂移（票实际已完成但 Status 未回写）列入对账发现，请示用户是否补置 done。每张一行「票号｜标题｜验收要点」
   - **待拍板/挂账**：🟡 记忆挂账＋票正文记录的开放问题，重复的合并
   - **建议下一步**：具体到命令——有票给 `/implement .scratch/<功能>/issues/NN-<slug>.md`；无票据项目给基于挂账或最近 commit 的可执行动作
   - **记忆健康**：一行——轻病 N 条／转介与否／孤岛有无；**记忆落后最近 commit 超过一批次→建议补跑 /checkpoint**
   完成＝简报交付；无票据项目简报依然成立（阶段/挂账/下一步都有来源）。

6. **全新项目分支**：空库且确认无孤岛→简报从票据与 git 现象重建，建议收尾 /checkpoint 建库；连票据都没有→建议 /project-init。
   完成＝简报交付。

7. **小修**：修复清单一批弹窗确认（推荐项放第一）→拍板后当场改记忆文件与索引（MEMORY.md 只做单行编辑）。
   完成＝清单每条要么已执行、要么用户明说挂起。

## 边界

只动记忆目录的行级小病。重写级手术与孤岛合并归 /memory-audit；repo 文档与票据治理归 /retro；票状态的正式回写属票的收口动作，本技能只发现漂移并请示。
