# 记忆纪律

orient（校验侧）、checkpoint（写入侧）、memory-audit（对账侧）共用的合同，也是**一切记忆写入**（含平台主动写入、日常临时写入）的总规矩——AGENTS.md 记忆套件地图指向这里。改纪律只改这一处。
总判据：长期层只放「丢失后会疼」的极小核——上下文是边际收益递减的有限资源。

## 四层地盘（每样东西只有一个真相源）

| 层 | 放什么 | 生命周期 |
|---|---|---|
| **repo**（票据/规格/plan docs/交付存档；含票与 PR 的评论） | 项目状态、进度细节、规格、流水账；完结记录统一进交付存档文件（如 docs/archive.md，没有就在收口时创建） | 永久，版本控制 |
| **/handoff**（OS 临时目录，Windows 为 %TEMP%） | 本会话工作状态 | 运输中的文档，落地即弃 |
| **平台记忆** | 两问测试通过的非显而易见事实 | 永久，定期体检 |
| **会话上下文** | 过程、工具输出、半成品 | 即弃 |

**票据终态约定**（repo 层，orient 对账与 checkpoint 收尾共用）：实现票收口＝验收勾选全勾＋Status 置终态——本地票本套件约定 `Status: done`，wayfinder 决策票＝`resolved`（走其 Resolve 全套），远端按 `docs/agents/issue-tracker.md` 关闭。

**记忆健康台账**（`.scratch/memory-health.md`，repo 层）：预警器的唯一计数器，机器可查。
- 一行一事：`日期｜类型｜内容`。类型三种：
  - `病`：orient 转介/落后/孤岛候选
  - `收口`：checkpoint **每轮**追加一行——有票记票数，无票记「轮 N」
  - `清账`：memory-audit 处置完追加的分界线
- 计数规则：orient 数「同一病名×同一对象自上次清账起出现次数」≥2→简报升级告警；距上次清账行的收口行满 2-3（票或轮）→建议跑 /memory-audit。
- 落点例外：无关联 repo 的会话落当前工作目录 `.scratch/`，并在简报注明落点。
- 孤岛裁决不记本台账，归全局台账 island-checks.md（四态与迁移规则见「记忆孤岛」节）。

**记忆孤岛**：同项目换工作区（搬目录/改名/换打开方式）会另起一套记忆目录。
- 位置：系统提示 memory 说明所指的根下（Bash 查 `~/.zcode/cli/memories/projects/`；用 Read 读候选文件时展开为 Windows 绝对路径）。
- 分工：orient 负责发现；/memory-audit 负责合并（带防护：合并前复述两库代表记忆供用户指认＋本库留溯源行＋不可逆处置推荐项默认保守）。
- 裁决落点：记忆根全局台账 `island-checks.md`（与各项目 memory 目录平级）——裁决四态＝确认/排除/待合并/已合并，一行一事 `日期｜目录名｜结论`。orient/audit 扫描先查它，已有结论的目录不再重复弹窗（跨窗口防重复的唯一稳定落点：孤岛诞生于换工作区，裁决不能留在会随窗口漂移的 repo 台账里）。历史孤岛裁决行留在旧台账不必迁移，以 island-checks.md 为准。文件不存在时 orient／audit 直接新建。
- 优先级：全局台账已有裁决的候选跳过发现问，但合并防护①仍必走（合并前安全步骤）。
- 多窗口：同项目可能绑定不同记忆目录——以项目语境指认的库为准，用 island-checks 与台账交叉印证。

## 两问测试（什么配进平台记忆）

一条事实同时过两问才写：

1. **下个月还为真吗？**——进行中的半成品、当次会话的临场信息不写（半成品→提醒用户跑 /handoff，记忆侧不写）。
2. **agent 能从仓库自行推出来吗？**——代码结构、进度细节、票面状态不写，至多留指针。

未验证但必须记的猜测→标注「假设：」。写成事实的假设会毒化后续所有推理；过时记忆比空记忆危害更隐蔽。

## 四种类型（一条记忆＝一个事实＝一个文件）

| type | 记什么 | 附加要求 |
|---|---|---|
| `user` | 用户是谁：角色、水平、偏好 | — |
| `feedback` | 工作方式的纠正与认可 | 正文必附 **Why:** 与 **How to apply:** |
| `project` | 项目约束、拍板决策、外部依赖、非显而易见的挂账 | 相对日期转绝对日期 |
| `reference` | 外部资源指针 | 链接＋一句用途 |

frontmatter＝文件开头的元数据块（name 与 description 供检索）：name 用短横线连接的小写英文名；description 是一行摘要——AI 搜记忆时据此判断是否读取全文，须与正文现状同步。frontmatter 三要素（name/description/type）缺一即病。

## 写入四问（动手前的过滤）

1. **repo 已记录？**→ 指针，不复制。
2. **会话结束即弃？**→ 提醒用户跑 /handoff，记忆侧不写。
3. **已有记忆覆盖同一事实？**→ 更新原文件（含 description 与索引钩子句），不新建。
4. **旧记忆已被推翻？**→ 修正或删除＋同步索引，不留残留条目。

## 重写律（project 型现状条目）

- 现状条目**整文件重写**，不做增量补丁：更新时拿旧版当输入，产出版只装「系统现在长什么样＋非显而易见的挂账」。矛盾与膨胀的根因就是只增不改。
- **落盘前重读**：写前重读目标文件与 MEMORY.md——与盘点时不一致（另一会话或平台主动写入动过）→重走查重与重写，不盲写。
- 进度细节（哪张票 done、测试数、commit 号）留 repo；它们出现在现状条目里＝越界信号。
- 单文件现状条目 ≤10KB；超线即删减至线内。

## 索引律（MEMORY.md）

- 一行一条：`- [标题](文件名) — 钩子句`，整行 ≤150 **字符**（按字符数计，不是字节；中文不要按字节计量）。标题＝description 的中文浓缩，与 description 同源——索引丢失后可照此重建，不丢语义。钩子句允许含 description 之外的导航信息（如指向设计史位置）——脱节判定只查「缺正文关键限定」。钩子句＝一行提示，据此快速判断是否读取；内容进正文，索引不装内容。
- **只做单行编辑**：更新索引用单行改写/追加，不整文件重写（防并发覆盖）。唯一例外＝memory-audit 的「重建索引」处置（用户拍板后整文件重写）。

## 体检红线（orient 轻体检与 memory-audit 校验基准）

- 断言带日期锚；被取代的口径删掉或标 superseded。
- 记忆与票面/git 对不上＝对账发现；**票面与记忆一致、但与 git/工作树矛盾的，也算发现**——两个记录可能一起过时。
- 现状条目含进度细节或 ✅ 条目＝重写律越界。
- 索引钩子句与 description/正文不一致＝发现（索引说谎比正文过时更隐蔽）。
- 索引行指向的文件不存在＝断链（病，处置见 memory-audit 的「对账」检查）。
- 正文链接记忆自身（[[自链]]）＝病，删。
- [[双链]] 指向不存在文件：目标 name 与库内现有记忆高度相近＝错链（病，修）；无相近者＝「将来值得写」的合法标记（超 60 天悬挂的列入 memory-audit 询问）。
- MEMORY.md 索引条目（`- [` 开头的行）≥30＝预警病：该瘦身了，转介 /memory-audit（删除／合并／搬进存档，处置全过拍板）——MEMORY.md 是唯一常驻上下文的记忆层，条数无界＝每次会话持续付上下文税。
