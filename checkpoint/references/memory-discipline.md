# 记忆纪律

orient（校验侧）、checkpoint（写入侧）、memory-audit（对账侧）共用的合同，也是**一切记忆写入**（含平台主动写入、日常顺手写入）的总规矩——AGENTS.md 记忆套件地图指向这里。改纪律只改这一处。
判据来自业界实证（多源独立提出）：上下文是边际收益递减的有限资源，长期层只放「丢失后会疼」的极小核。

## 四层地盘（每样东西只有一个真相源）

| 层 | 放什么 | 生命周期 |
|---|---|---|
| **repo**（票据/规格/plan docs/交付存档） | 项目状态、进度细节、规格、流水账 | 永久，版本控制 |
| **/handoff**（OS 临时目录，Windows 为 %TEMP%） | 本会话工作状态 | 运输中的文档，落地即弃 |
| **平台记忆** | 两问测试通过的非显而易见事实 | 永久，定期体检 |
| **会话上下文** | 过程、工具输出、半成品 | 即弃 |

**记忆孤岛**：同项目换工作区（搬目录/改名/换打开方式）会另起一套记忆目录。位置在系统提示 memory 说明所指的根下（Bash 查 `~/.zcode/cli/memories/projects/`；用 Read 读候选文件时展开为 Windows 绝对路径）。orient 负责发现，/memory-audit 负责合并。

## 两问测试（什么配进平台记忆）

一条事实同时过两问才写：

1. **下个月还为真吗？**——进行中的半成品、当次会话的临场信息不写（半成品→提醒用户跑 /handoff，记忆侧不写）。
2. **agent 能从仓库自行推出来吗？**——代码结构、进度细节、票面状态不写，顶多留指针。

未验证但必须记的猜测→标注「假设：」。写成事实的假设会毒化后续所有推理；过时记忆比空记忆更阴险。

## 四种类型（一条记忆＝一个事实＝一个文件）

| type | 记什么 | 附加要求 |
|---|---|---|
| `user` | 用户是谁：角色、水平、偏好 | — |
| `feedback` | 工作方式的纠正与认可 | 正文必附 **Why:** 与 **How to apply:** |
| `project` | 项目约束、拍板决策、外部依赖、非显而易见的挂账 | 相对日期转绝对日期 |
| `reference` | 外部资源指针 | 链接＋一句用途 |

frontmatter：`name` 短横线小写 slug；`description` 一行摘要——召回靠它判断相关性，须与正文现状同步。

## 写入四问（动手前的过滤）

1. **repo 已记录？**→ 指针，不复制。
2. **会话结束即弃？**→ 提醒用户跑 /handoff，记忆侧不写。
3. **已有记忆覆盖同一事实？**→ 更新原文件（含 description），不新建。
4. **旧记忆已被推翻？**→ 修正或删除＋同步索引，不留尸体。

## 重写律（project 型现状条目）

- 现状条目**整文件重写**，不做增量补丁：更新时拿旧版当输入，产出版只装「系统现在长什么样＋非显而易见的挂账」。矛盾与膨胀的根因就是只增不改。
- **落盘前重读**：写前重读目标文件与 MEMORY.md——与盘点时不一致（另一会话或平台主动写入动过）→重走查重与重写，不盲写。
- 进度细节（哪张票 done、测试数、commit 号）留 repo；它们出现在现状条目里＝越界信号。
- 单文件现状条目 ≤10KB；超线即瘦身。

## 索引律（MEMORY.md）

- 一行一条：`- [标题](文件名) — 钩子句`，整行 ≤150 字符。
- 钩子句＝扫一眼决定「读不读全文」；内容进正文，索引不装内容。
- **只做单行编辑**：更新索引用单行改写/追加，不整文件重写（防并发互踩）。

## 体检红线（orient 轻体检与 memory-audit 校验基准）

- 断言带日期锚；被取代的口径删掉或标 superseded。
- 记忆与票面/git 对不上＝对账发现；**票面与记忆一致、但与 git/工作树矛盾的，也算发现**——两个记录可能一起过时。
- 现状条目含进度细节或 ✅ 条目＝重写律越界。
- [[双链]] 指向不存在文件的链接＝「将来值得写」的标记，合法。
