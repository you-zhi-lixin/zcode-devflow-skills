# checkpoint（收口沉淀）

用户喊 /checkpoint 或「更新项目记忆」。任务：把本段工作里**将来会丢**的知识存进记忆，其余一切留在 repo。

先读 [memory-discipline.md](references/memory-discipline.md)（读不到→停下告知用户）。两问测试、写入四问、重写律全在那份合同里，本文件不重复。

## 过程

1. **盘点本段产出**：本会话产生或参与的提交（`git log --oneline`）、票据状态变化、对话里的拍板、新踩的坑、用户对工作方式的纠正。用户传了参数就以参数为盘点重点。**本会话经历过压缩（compaction）→对话来源不可靠：以 git log/票面/diff 为准，对话项逐条向用户确认，拿不准标「假设：」或不写。** 工作区有未提交改动→先请示是否 commit 再盘点。
   完成＝产出清单在手，每项标来源（票／commit／对话）。

2. **过两问测试＋写入四问**：进度细节（票 done、测试数、commit 号）留 repo 不进记忆；会话级半成品→**提醒用户跑 /handoff**（手动技能，本技能无法代调），记忆侧不写；值得写的→归入四种类型并标落点。交付流水账→追加进 repo 存档或史册文件，记忆留指针。拿不准的猜测→标「假设：」。
   完成＝候选清单，每条标类型与落点。

3. **查重与重写**：候选逐条对 MEMORY.md 和相近记忆——覆盖同一事实→更新原文件（description 同步）；被本段工作推翻→修正或删除＋同步索引。project 型现状条目按重写律整文件重写：拿旧版当输入，产出版只装「现在长什么样＋非显而易见的挂账」，✅ 与进度细节清出去。拿不准删不删、翻不翻口径的→弹窗带推荐拍板；其余直接落。
   完成＝写入方案定型。

4. **落盘（防并发互踩）**：写前重读目标文件与 MEMORY.md——与盘点时不一致（另一会话或平台主动写入动过）→重走第 3 步再写；MEMORY.md 只做单行编辑，不整文件重写。
   完成＝文件与索引已更新，未覆盖他人写入。

5. **报变更清单**：新建 N／更新 M／删除 K，每条一行「动作｜记忆名｜一句话理由」；删除与口径翻转的注明波及哪些旧结论。
   完成＝用户能从清单一眼核对这轮记忆动了什么。
